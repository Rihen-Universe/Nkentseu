NKENTSEU_PURE_FUNCTION

#
macro
#define NKENTSEU_PURE_FUNCTION

Indique qu'une fonction n'a pas d'effets de bord

Permet au compilateur d'optimiser agressivement les appels. La fonction ne doit pas modifier l'état global ni dépendre de variables volatiles.

@codefragment, non compilé
NKENTSEU_PURE_FUNCTION int Square(int x) { return x * x; }

NKENTSEU_CONST_FUNCTION

#
macro
#define NKENTSEU_CONST_FUNCTION

Indique qu'une fonction dépend uniquement de ses paramètres

Plus restrictif que PURE : la fonction ne lit aucune variable globale. Permet des optimisations supplémentaires comme la CSE (Common Subexpression Elimination).

@codefragment, non compilé
NKENTSEU_CONST_FUNCTION int Add(int a, int b) { return a + b; }

Indique que la fonction est improbable d'être appelée

Aide le compilateur à optimiser le layout du code en plaçant les fonctions "froides" (error handlers, init rare) loin du hot path.

Indique que la fonction est très probable d'être appelée

L'inverse de COLD : place la fonction dans une section optimisée pour le cache. À réserver aux fonctions critiques du hot path.

NKENTSEU_LIKELY

#
macro
#define NKENTSEU_LIKELY(condition)

Indique qu'une condition est probablement vraie

Optimise le layout du code pour que le chemin "vrai" soit contigu. Réduit les défauts de prédiction de branche sur CPU modernes.

@codefragment, non compilé
if (NKENTSEU_LIKELY(ptr != nullptr)) {
    // Hot path : code fréquemment exécuté
    ProcessData(ptr);
} else {
    // Cold path : gestion d'erreur rare
    HandleNullPointer();
}
Source : NkPlatformInline.h, ligne 313

NKENTSEU_UNLIKELY

#
macro
#define NKENTSEU_UNLIKELY(condition)

Indique qu'une condition est probablement fausse

Optimise le layout pour que le chemin "faux" soit le hot path. Idéal pour les checks d'erreur ou les assertions en release.

@codefragment, non compilé
if (NKENTSEU_UNLIKELY(errorCode != 0)) {
    LogError(errorCode);
    return false;
}
// Hot path continue ici sans saut
